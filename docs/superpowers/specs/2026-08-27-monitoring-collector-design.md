# Сборщик «Карты мониторинга» — дизайн v1

**Дата:** 27.08.2026
**Статус:** согласован, ждёт плана реализации

---

## 1. Контекст

Модуль «Карта мониторинга» существует как документы, конфиги, JSON-схемы и SQL-миграция. Он описывает, что отслеживать и как оценивать, но ничего не собирает: в проекте нет ни одной строки исполняемого кода, кроме двух проверялок согласованности.

Задача v1 — сделать так, чтобы карта заработала на живых данных.

**Главная неопределённость, которую снимает v1.** Пороги 80/60/40 и веса матрицы заданы умозрительно и никогда не проверялись потоком. Пока через них не пройдут настоящие материалы, неизвестно, отсекают они мусор или полезное. Поэтому v1 оптимизируется не под охват источников, а под то, чтобы **матрица впервые отработала на реальных данных и её можно было откалибровать**.

---

## 2. Границы v1

**Входит:** сбор из двух типов источников, стоп-правила, проставление 14 факторов, подсчёт баллов и полос, heartbeat из десяти вопросов, дайджест в Telegram.

**Не входит:** Telegram-каналы как источник (нужен MTProto и отдельный аккаунт), госреестры, площадки P4, детектор массовости (без потока T5/T6 ему не на чем работать), фактчекинг, четыре гейта публикации, написание постов, модерация с кнопками.

Дайджест — тонкий слой отчётности, а не та доставка редактору, что описана в `docs/03-handoff.md` §6. Кнопок и решений в нём нет.

## 3. Принятые решения

| # | Решение | Обоснование |
|---|---|---|
| **D1** | Матрица определяет приоритет очереди, а не публикацию | Взвешенная сумма допускает компенсацию: слух без подтверждения набирает 115 − 50 = 65 и по шкале ТЗ проходит в работу. Гейты публикации соединены через AND и живут downstream |
| **D2** | v1 = сбор + триаж + heartbeat + дайджест | Даёт замкнутый контур: видно, работает ли матрица, без построения всей редакции |
| **D3** | Без поискового API, но со швом под него | Поискового ключа нет, он платный. Самый ценный сигнал — `doc_diff` — поиска не требует. 89 запросов работают матчерами тем и площадок |
| **D4** | PostgreSQL в Амвере, не SQLite | Готовая миграция применяется как есть. Снимает риск двух расходящихся схем |
| **D5** | Классификатор гибридный | 7 факторов считаются кодом бесплатно и воспроизводимо, 7 требуют суждения и идут в Claude пачками |
| **D6** | Два коллектора, полный тракт | Источники — строки в конфиге, добавляются за вечер. Триаж к широкому сбору достроить дороже |
| **D7** | Дайджест в существующий `@CMZakaz_Bot` | Токен и chat_id уже есть в `C:\Контент Мейкер\video\.env` |
| **D8** | `app.py` поддерживает `--once` и режим цикла | У Амверы есть Cron Jobs — короткий тик по расписанию дешевле постоянного контейнера. Разница в пять строк, выбор откладывается до первых замеров |

## 4. Архитектура

```
app.py                    точка входа: --once | цикл; расписание классов A–F
monitoring/
  config.py               загрузка и валидация четырёх YAML при старте
  db.py                   пул к Postgres, идемпотентная миграция, репозитории
  collectors/
    base.py               HTTP: retry, rate limit, ETag/Last-Modified, User-Agent с контактом
    doc_diff.py           снапшот → нормализация DOM → хеш → сравнение → семантический diff
    rss.py                feedparser, нормализация дат
  normalize.py            любой источник → единый source_item
  stop_rules.py           14 правил, каждое возвращает код причины или None
  factors/
    mechanical.py         7 факторов кодом
    judgment.py           7 факторов через Claude, пачками по 15–20
  scoring.py              сумма, полосы, тай-брейк, подъём из BACKLOG
  heartbeat.py            10 вопросов с возрастом данных
  delivery.py             дайджест и срочные находки в Telegram
```

### Границы модулей

**`scoring.py` — чистая функция.** На входе словарь факторов, на выходе сумма и полоса. Никакого ввода-вывода. Вся матрица живёт здесь и покрывается тестами без сети и базы. Аргумент из `docs/01-triage-scoring.md` §3 про слух на 65 баллов становится обычным юнит-тестом.

**Разделение `mechanical` / `judgment`** повторяет каскад стоимости: механическое считается всегда и бесплатно, Claude зовётся только за семью факторами и только для того, что прошло стоп-правила. В тестах `judgment` подменяется заглушкой, и весь тракт проверяется без API.

**`stop_rules.py` стоит до `scoring.py`**, как требует `docs/01-triage-scoring.md` §4. Отсев пишется в `stop_rule_drops` с кодом причины.

**Шов под поиск.** `collectors/search.py` появится позже с тем же интерфейсом, что у `rss.py`. Остальные модули не меняются.

## 5. Поток данных

```
созрел класс → коллекторы → normalize → дедуп по url_hash
  → stop_rules ──сработало──→ stop_rule_drops, конец
  → mechanical (7 факторов)
  → judgment (7 факторов, пачкой)      [пропускается, если Claude недоступен]
  → scoring → monitoring_hits + triage_transitions

раз в 5 минут независимо:
  подъём из BACKLOG → heartbeat → доставка
```

Цикл просыпается раз в минуту и смотрит, каким классам пора. Это проще шести таймеров, а классу A пятиминутный ритм даётся сам собой.

**Доставка разделена.** `URGENT` уходит немедленно. `QUEUE` и `BACKLOG` копятся в дайджест дважды в день. Пустые тики пишутся в базу, но не отправляются — иначе бот превратится в ленту «нового нет».

## 6. Данные

### Правка существующей миграции

`sql/001_monitoring_map.sql` написана однократной: `CREATE TYPE` и `CREATE TABLE` без `IF NOT EXISTS`. При втором старте сервиса она упадёт. Postgres не поддерживает `IF NOT EXISTS` для `CREATE TYPE`, поэтому нужны `DO`-блоки:

```sql
DO $$ BEGIN
    CREATE TYPE triage_decision AS ENUM ('URGENT','QUEUE','BACKLOG','DROP');
EXCEPTION WHEN duplicate_object THEN NULL;
END $$;
```

Таблицы переводятся на `CREATE TABLE IF NOT EXISTS`, индексы — на `CREATE INDEX IF NOT EXISTS` (для этого им нужны явные имена). Проверялка `tools/check_sql.py` дополняется тестом на повторное применение.

### Новый конфиг `config/sources.yaml`

Реестр источников: ключ, название, тир, способ сбора (`doc_diff` или `rss`), URL, класс частоты, площадка. Адреса лент меняются, поэтому каждый источник проходит онбординг при первом запуске: три успешных запроса, разбор дат у ≥80% элементов, доля релевантного. Не прошедшие получают `needs_review` и попадают в дайджест, а не молча отваливаются.

Валидация подключается к существующей `tools/validate.py` — проверка остаётся одна.

## 7. Отказы

| Ситуация | Поведение |
|---|---|
| Источник молчит 3 интервала | `needs_review`, период ×2, строка в дайджест |
| HTTP 429 | Экспоненциальная пауза, позиция опроса не теряется |
| Claude недоступен | Тик выполняет детерминированную часть; элементы копятся с `awaiting_classification` и доклассифицируются позже |
| База недоступна | Тик падает, следующий повторяет. Сбор идемпотентен по `url_hash`, терять нечего |
| Тик не успел за интервал | Следующий не запускается параллельно, пишется `SKIPPED_OVERLAP` |
| Telegram недоступен | Дайджест откладывается до следующего тика, находки не теряются |

## 8. Тестирование

Основной вес — на `scoring.py`:

- три эталонных случая из `docs/01-triage-scoring.md` §2.3 (130 / 55 / 65);
- границы полос: 39/40, 59/60, 79/80;
- подъём из `BACKLOG`: 65 + 65 = 130 и переход в `URGENT`.

Дальше:

- по фикстуре на каждое из 14 стоп-правил;
- `mechanical.py` — таблица входов и ожидаемых факторов;
- `doc_diff.py` — два снапшота с ожидаемым diff и **отдельный тест, что шум не даёт ложного срабатывания**: счётчики просмотров, даты рендера, перестановка рекламных блоков. Это главный источник мусора в таких коллекторах;
- `heartbeat.py` — валидация вывода против `schemas/heartbeat.schema.json`;
- сухой прогон `--dry-run`: настоящий сбор, без записи в базу и без отправки.

## 9. Деплой

`amvera.yml`:

```yaml
meta:
  environment: python
  toolchain:
    name: pip
    version: 3.12
run:
  scriptName: app.py
  persistenceMount: /data
```

На `/data` лягут снапшоты страниц — без них `doc_diff` не с чем сравнивать.

Секреты задаются переменными окружения в панели Амверы и в репозиторий не попадают: `DATABASE_URL`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.

**Что делает Давид в Амвере:** создаёт проект PostgreSQL (тариф не ниже «Начальный», 290 руб/мес), создаёт приложение (тариф «Начальный», 290 руб/мес), прописывает четыре переменные окружения. Итого ≈580 руб/мес с поминутной тарификацией.

### Про картинки — что учесть, когда дойдём

Это **не входит в v1**: постов ещё нет, прикреплять картинку не к чему. Заход следующий.

Готовый прецедент — `C:\Тг группа\tg-ai-news\cover.py`: Pillow, 1280×720, тёмный градиент, крупный заголовок с кириллицей, плашка бренда. Бесплатно и локально, переиспользуется почти целиком.

**Ловушка при переносе.** В нём зашиты пути к шрифтам Windows:

```python
FONT_BOLD = "C:/Windows/Fonts/seguibl.ttf"
```

В контейнере Амверы это Linux, таких файлов нет — обложки молча упадут на старте. Шрифт с кириллицей нужно положить в репозиторий и брать путь относительно проекта.

Для генерации: у Давида есть `YANDEX_API_KEY`, но он от SpeechKit — для Yandex ART нужны свои права сервисного аккаунта. Бесплатная альтернатива — Kandinsky от Сбера. Через OpenRouter картиночные модели тоже есть, но их набор уже, чем у текстовых.

## 12. Открытые вопросы

1. **Cron Jobs или постоянный контейнер.** Решается после первых замеров длительности тика. `app.py` поддерживает оба режима, так что цена ошибки — нулевая.
2. **Частота дайджеста.** Заложено дважды в день, вынесено в конфиг.
3. **Стартовый список источников.** Составляю кандидатов, Давид смотрит и дополняет. Онбординг отсеет нерабочие адреса автоматически.
