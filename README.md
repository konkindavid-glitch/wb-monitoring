# Карта мониторинга

Модуль автопостинга, который системно наблюдает за полем маркетплейсов, e-commerce и AI: описывает **что** отслеживать, **как это оценивать** и **в каком порядке брать в работу**.

Не поиск по словам «Wildberries» и «Ozon». Карта задаёт пространство наблюдения по четырём осям — площадки, темы, сигналы, стоп-лист — и для каждой находки выдаёт разбор оценки и полосу очереди.

**Главный вопрос, на который обязан отвечать любой материал:**

> Селлер прочитал это — он заработает, не потеряет деньги, избежит риска или быстрее примет решение?

---

## Три решения, которые определяют конструкцию

**1. Матрица баллов определяет приоритет, а не публикацию.**
Матрица из ТЗ — взвешенная сумма, и она допускает компенсацию: слух без подтверждения набирает 115 − 50 = **65 баллов** и по шкале ТЗ попадает в «готовить пост». Поэтому матрица решает только, за что браться первым. Разрешение на публикацию остаётся за четырьмя независимыми гейтами через AND, которые живут downstream. Разбор — [docs/01-triage-scoring.md](docs/01-triage-scoring.md) §3.

**2. Пять минут там, где это окупается.**
Полный обход 89 запросов каждые 5 минут — 288 прогонов в сутки, rate limit источников и оплата пустых запросов. Класс A (5 минут) закреплён за Wildberries и детектором сбоев; остальное — по классам B–F. Разбор — [docs/02-cadence.md](docs/02-cadence.md).

**3. Расширение тематики — записанное решение, а не побочный эффект.**
Тринадцать площадок второго эшелона и темы AI, трендов и потребительского поведения добавлены сознательно 27.08.2026, с порогом входа. [docs/00-monitoring-map.md](docs/00-monitoring-map.md) §6.

## Проверка

```bash
PYTHONUTF8=1 python tools/validate.py
```

81 проверка согласованности «документ ↔ YAML ↔ схема ↔ SQL»: полнота запросов против ТЗ, совпадение перечислений во всех четырёх местах, арифметика матрицы на трёх эталонных случаях, валидация примеров из документов по JSON Schema. Отчёт пишется в `tools/validation-report.txt`.

```bash
PYTHONUTF8=1 python tools/check_sql.py
```

14 проверок миграции: разбор парсером PostgreSQL, состав таблиц и типов, разрешимость внешних ключей, наличие обещанных документами ограничений. Отчёт — `tools/sql-check-report.txt`.

> **Миграция нигде не применялась.** На этой машине нет ни `psql`, ни Docker, поэтому SQL проверен только статическим разбором. При развёртывании применить: `psql -f sql/001_monitoring_map.sql`.

Зависимости проверялок: `pyyaml`, `jsonschema`, `sqlglot`.

**Про кодировку.** Системная кодовая страница на этой машине — cp1251, и кириллица в консоли приходит мусором. Проверялки печатают только латиницу, а полные отчёты пишут файлами в UTF-8 — результат смотреть в файле, а не по выводу в терминал.

## Границы модуля

Карта — это правила и хранилище решений. Не входит в модуль и должно быть построено отдельно:

- коллекторы источников (HTTP, сравнение снапшотов, Telegram);
- реестр источников с тирами и рейтингом доверия;
- классификатор, проставляющий факторы матрицы;
- фактчекинг и четыре гейта публикации — интерфейс описан в [docs/03-handoff.md](docs/03-handoff.md) §3;
- доставка редактору.

Проработанная архитектура этих слоёв существует отдельно — `C:\Ведение группы в телеграм`. Словарь категорий здесь намеренно совпадает с её `event_category`, чтобы стыковка не потребовала переразметки накопленного.
